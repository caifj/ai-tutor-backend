# 代码相似度审查说明

## 工作流程

带有 `source_code` 的案例提交会经过后端统一的代码相似度审查：

1. 从 SQLite 的 `code_submissions` 表读取相同 `case_id` 的历史源码；
2. 排除相同 `student_id` 的历史提交，避免学生修改自己代码时被误判；
3. 计算与其余历史提交的最高相似度；
4. 达到阈值时扣减 `payload.metrics.overall_score`，并写入结构化诊断；
5. 保存本次源码，供后续同案例提交比较。

源码按案例隔离，案例 A 的代码不会参与案例 B 的查重。查重指标属于标准结果中的
`metrics`，因此 JSON 页面和 CSV 导出都可以读取。

## 默认规则

- 默认阈值：85%；
- 85% 开始扣 10 分；
- 相似度越高扣分越多，100% 相同时最多扣 30 分；
- 少于 40 个有效代码标记的短代码不参与自动判定；
- 忽略空白、换行、注释和缩进差异；
- 字符串、数字常量和普通标识符会进行归一化，再结合原始标记序列计算局部代码片段的
  Jaccard 相似度；
- 自动结果只表示代码结构相似，不等同于最终学术不端认定，教师应结合题目模板与学生
  解释进行复核。

可通过环境变量调整：

```powershell
$env:AI_TUTOR_SIMILARITY_THRESHOLD = "0.85"
$env:AI_TUTOR_SIMILARITY_MAX_PENALTY = "30"
```

阈值允许范围为 `0.50` 至 `0.99`，最大扣分允许范围为 `1` 至 `100`。

## 输入身份

前端首次打开时在浏览器 `localStorage` 中生成匿名 `student_id`，提交时写入请求的
`metadata.student_id`。该标识用于排除同一浏览器中的个人迭代，不包含姓名、学号或邮箱。

当前项目没有登录系统，因此匿名标识只能满足演示和原型需要。正式教学环境应使用登录后
由服务端签发的学生标识，不能信任浏览器自行提交的身份字段。

## 结果字段

代码提交的 `payload.metrics` 增加：

| 字段 | 含义 |
| --- | --- |
| `similarity_checked_submissions` | 本次参与比较的同案例历史代码数量 |
| `similarity_score` | 最高相似度百分比 |
| `similarity_threshold` | 当前扣分阈值百分比 |
| `similarity_penalty` | 实际查重扣分 |
| `original_score` | 触发扣分时的原始总分 |
| `overall_score` | 扣分后的最终总分 |

超过阈值时还会增加 `CODE_SIMILARITY_HIGH` 警告诊断。响应不会返回其他学生的身份、
文件名或源码。

## 存储与隐私

源码保存在后端数据库 `backend/var/ai_tutor.db` 的 `code_submissions` 表，不保存在 AI 模型服务中，
也没有提供读取源码的 HTTP 接口。正式部署前仍应补充：

- 数据库访问控制与磁盘加密；
- 按课程结束时间设置源码保留期限和删除机制；
- 明确告知学生查重用途、扣分规则与申诉流程；
- 对高相似结果进行教师复核，而不是仅凭自动分数作出纪律认定。
