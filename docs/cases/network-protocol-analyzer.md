# 案例 3：网络协议分析仪代码评测

## 目标与边界

本案例接收学生提交的单个 `.py` 文件，判断代码是否覆盖原案例要求：

- 构造 ARP、ICMP、TCP 报文。
- 捕获网络报文。
- 解析 ARP、ICMP、TCP 字段。
- 识别端口扫描、主机扫描等异常流量。
- 输出抓包记录和异常识别结果。

Case 3 只负责案例专属的运行测试与协议指标分析：基座把代码提交给独立沙箱完成编译和
运行，运行测试注入 Scapy 替身和模拟报文，不访问服务器真实网卡，也不允许学生代码访问
Web 后端环境、数据库或 AI Key。PEP8、模块化程度和跨提交查重由基座统一执行；Case 3
不再使用 AST 推断协议功能，也不再包含安全调用等其他静态规则。

核心文件：

```text
backend/cases/case_03_network_protocol_analyzer/
  code_grader.py  案例描述、输入校验与标准化输出
  runtime_harness.py  Case 3 专用模拟报文测试夹具
```

基座中的 `static_evaluation.py` 负责 PEP8 和模块化程度，`code_similarity.py` 负责按案例
隔离的跨提交重复代码检测。

## Web 使用方式

1. 启动后端并打开 `http://127.0.0.1:8000/`。
2. 进入“网络协议分析仪代码评测”。
3. 填写提交人，并选择或拖入一个不超过 500 KB 的 `.py` 文件。
4. 点击“提交并评测”，查看通过率、总分、基座返回报文、分项检查和改进建议。
5. 再次提交后，可在“本机提交时间线”选择历史版本并查看逐行差异。同一提交人的历史版本
   不会互相触发查重扣分。

页面不会提供源码文本框或协议参数表单，文件扩展名和大小会在浏览器与后端两端校验。
可直接使用仓库中的 `backend/cases/case_03_submission.py` 验证完整流程。

## HTTP 请求

浏览器读取文件文本后仍通过统一 JSON 接口提交：

```json
{
  "case_id": "network.protocol-analyzer",
  "input": {
    "filename": "student_analyzer.py",
    "source_code": "from scapy.all import ARP, ICMP, TCP, sniff\n..."
  },
  "metadata": {"submitter": "20260001"}
}
```

`source_code` 最大 500,000 字符；`filename` 必须以 `.py` 结尾。接口保持 JSON/CSV 标准输出，
源码会按本案例单独保存在后端并参与后续学生提交的相似度审查；超过默认 85% 阈值时会
扣减总分。完整规则见 [../code-similarity.md](../code-similarity.md)。
其中 CSV 通过结果下载入口生成。

评测结果页面会在“问题与改进建议”区域异步生成一段 AI 点评，最多 100 个字符。点评只向
模型发送结构化评分与问题摘要，不发送学生源码；模型不可用时不影响代码评测结果。

## 评分组成

总分为 100 分：

- 案例功能 80 分：完全来自隔离沙箱中的 9 项运行测试，Case 3 负责分析协议指标。
- PEP8 规范 10 分：长行、Tab 缩进、行尾空白、通配符导入和命名等启发式检查。
- 模块化程度 10 分：函数/类拆分、文档字符串和超长函数。
- 重复代码检测：基座按案例比较不同提交人的历史代码；超过阈值后从上述总分中扣分，同一
  提交人的版本迭代不扣分。

输出数据集：

- `runtime_tests`：模拟报文环境中的实际函数调用与通过状态。
- `runtime_packets`：基座返回的 ARP、ICMP、TCP 模拟报文，包含阶段、源/目标地址和字段。
- `runtime_observations`：ARP、ICMP、TCP 字段和扫描告警等结构化运行输出。
- `quality_scores`：基座生成的 PEP8、模块化程度和重复代码检测结果。
- `code_issues`：问题级别、行号、规则编号和修复建议。

前端将功能与质量明细展示为可展开面板；原始 JSON 与 CSV 仍可用于后续系统对接。

## 浏览器缓存方案

可以通过浏览器缓存实现本机演示，本项目使用 **IndexedDB**，不使用 `localStorage`：

- 每次评测保存源码、文件名、时间、标准结果和请求 ID。
- 时间线按提交时间倒序展示。
- 时间线可按提交人筛选，记录中会显示提交人；版本对比也限定在当前筛选范围内。
- 任意两个本机版本可进行逐行差异比较。
- 数据只保存在当前浏览器和当前站点，不会自动跨设备同步。

清理浏览器站点数据、使用隐私模式或更换浏览器都会导致历史丢失。IndexedDB 适合原型演示，
但不适合作为正式教学档案。正式环境应把提交版本保存到受权限控制的服务端数据库，并定义
保留期限、容量限制和隐私策略。

## 评测限制

- 动态测试使用模拟报文，不代表学生代码拥有真实网卡权限，也不验证真实网络吞吐量。
- 沙箱不可用时无法完成案例功能测评，结果会明确标记运行器不可用；不会再以 AST 关键词
  推断代替实际功能测试。
- 当前 PEP8 评分是轻量启发式实现，不等同于完整 Ruff/Pylint 检查。
- 页面显示的结论应作为自动初筛，并允许教师展开证据后人工复核。
